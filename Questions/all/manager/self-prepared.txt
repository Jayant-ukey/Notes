 What Was the Toughest Production Issue You Handled?

"One of the toughest production issues I handled was a port exhaustion problem that surfaced after a release went live.
After the deployment, we started noticing that clients with higher usage volumes were experiencing application crashes. On investigation, we found that the system was running into port exhaustion — all available ports were getting held up and the application had no ports left to establish new connections, causing it to crash.
The immediate priority was to restore service availability. We restarted the application to release the held ports and bring the system back online for the affected clients.
Once the system was stable, I did a thorough root cause analysis by going through the codebase. I identified that there were multiple places in the code where HttpConnections were being opened but never properly closed. These unclosed connections were accumulating over time, holding onto ports and eventually exhausting the available pool — which only became visible under higher client load.
The fix I implemented was to properly close all HttpConnections using the try-with-resources pattern in Java, which ensures connections are automatically closed even if an exception occurs. I applied this fix across all the affected areas, packaged it as a patch, and deployed it.
After the patch was released, the port exhaustion issue was completely resolved and the application has been stable ever since.
The key lesson I took from this was the importance of resource management in Java and how issues that seem invisible in low-traffic environments can become critical failures at scale. After this, I also advocated for adding connection-related metrics to our Splunk monitoring dashboard so such issues could be caught earlier in the future."
